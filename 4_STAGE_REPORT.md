### 2.2. Изменяемые теги GitHub Actions

В workflow используются ссылки на действия по тегам: `actions/checkout@v7`, `gitleaks/gitleaks-action@v3`, `actions/upload-artifact@v4`, `aquasecurity/trivy-action@v0.36.0`, `docker/login-action@v4`. Тег может быть перезаписан владельцем действия, что создаёт риск supply-chain атаки.

**Рекомендация:** закрепить каждое действие на полный 40-символьный SHA коммита.

### 2.3. Запуск контейнера от root

В `Dockerfile` отсутствует директива `USER` перед `CMD`. Процесс в контейнере запускается от `root`, что повышает риск компрометации контейнера.

**Рекомендация:** создать непривилегированного пользователя и переключиться на него.

### 2.4. Потенциальная инъекция команд в workflow

Semgrep не смог разобрать bash-сниппеты из-за конструкций `${{ github.event.before }}` и `${{ steps.version.outputs.version }}`. В workflow эти выражения подставляются непосредственно в shell-команды (`git fetch`, `docker build`, `docker push`), что при определённых условиях может привести к инъекции команд.

**Рекомендация:** передавать значения через `env` и использовать кавычки; ограничить `permissions` для `GITHUB_TOKEN`.

## 5. Рекомендации по коду

### 5.1. `Dockerfile`

- Базовый образ `python:3.12-slim` **не закреплён на digest** — при пересборке может подтянуться другая версия.
- Отсутствует `USER` — контейнер работает от `root`.
- Не выполняется обновление пакетов Debian, что оставляет уязвимости уровня HIGH в базовом образе.

**Рекомендации:**

```dockerfile
FROM python:3.12-slim@sha256:<digest>

RUN apt-get update \
    && apt-get upgrade -y \
    && rm -rf /var/lib/apt/lists/*

RUN useradd -m appuser
USER appuser
```

### 5.2. `requirements.txt`

Зависимости `fastapi` и `uvicorn[standard]` **не имеют фиксации версий**. При каждой сборке могут устанавливаться разные версии пакетов, что снижает воспроизводимость и повышает риск supply-chain атак.

**Рекомендация:** зафиксировать точные версии (или использовать lock-файл) и настроить Dependabot для контролируемого обновления.

### 5.3. `.github/workflows/docker-publish.yml`

Помимо изменяемых тегов и потенциальной инъекции команд:

- **Semgrep запускается с `continue-on-error: true`** — находки не блокируют пайплайн.
- **Trivy запускается с `exit-code: '0'`** — даже при наличии HIGH/CRITICAL уязвимостей сборка и публикация образа продолжаются.

Уязвимый образ может быть опубликован в GHCR. Для повышения безопасности можно:

- установить `exit-code: '1'` для Trivy при наличии HIGH/CRITICAL;
- убрать `continue-on-error` для Semgrep или, как минимум, ужесточить правила;
- ограничить `permissions` для `GITHUB_TOKEN` до минимально необходимых.

## 7. Вывод

По результатам анализа:

- **Gitleaks** не обнаружил утечек секретов;
- **Semgrep** выявил критичную проблему запуска контейнера от `root`, предупреждения об изменяемых тегах GitHub Actions и косвенные признаки потенциальной инъекции команд в workflow;
- **Trivy** выявил 8 уникальных CVE уровня HIGH в базовых пакетах Debian и 6 уязвимостей в Python-пакете `pip`; для всех есть исправленные версии, но установленные в образе версии уязвимы;
- в коде калькулятора **не используются `eval()` и `exec()`** — вычисления безопасны, однако отсутствуют ограничения ресурсов и фиксация версий зависимостей;
- CI/CD-пайплайн **не блокирует публикацию** при наличии уязвимостей (`continue-on-error` для Semgrep и `exit-code: '0'` для Trivy).
